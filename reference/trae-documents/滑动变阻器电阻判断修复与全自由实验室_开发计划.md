# 滑动变阻器电阻判断修复 + 全自由实验室 开发计划

版本：v1.4.0（2026-10-23）

## 一、摘要

1. **修复滑动变阻器“接入电阻判断”错误**：当前把“接入电阻”一律当作 `slider × max`，与接线柱选择无关。实际使用下端 B 柱时应为 `(1 − slider) × max`，接 A+B 时应为 `max`，只接上端应为 0。同时实验二的“滑片移到阻值最大端”判定也硬编码为 `slider ≥ 0.95`，接 B 柱时判断错误。
2. **新增独立“全自由电学实验室”**：首页第 4 张卡片，空白画布 + 全部 7 种元件 + 不限数量 + 自定义参数，无步骤、无结论题，保留仪表读数与记录/导出。

## 二、现状分析

### 2.1 变阻器求解模型本身是对的，导出信息是错的

- [circuit.js](file:///d:/Trae/temp_20261022_02/assets/js/core/circuit.js#L227-L232) 中 `a–S = slider·max`、`b–S = (1−slider)·max`，c/d 合并到内部滑片节点 S（L180-185），**物理模型正确**。
- 但 [circuit.js](file:///d:/Trae/temp_20261022_02/assets/js/core/circuit.js#L424-L439) 只输出 `wiring / bottoms / tops`，不输出“实际接入电阻”“哪一端阻值最大”，导致下游全部靠猜。
- [board.js](file:///d:/Trae/temp_20261022_02/assets/js/core/board.js#L268-L278) 画布上的阻值文字固定写 `slider × max`。
- [app.js](file:///d:/Trae/temp_20261022_02/assets/js/app.js#L667-L670) 与 [app.js](file:///d:/Trae/temp_20261022_02/assets/js/app.js#L706-L713) 属性面板同样固定写 `slider × max`。
- 实验二 [lab-ohm-r.js](file:///d:/Trae/temp_20261022_02/assets/js/labs/lab-ohm-r.js#L49-L52) 用 `slider >= 0.95` 判“最大端”，[lab-ohm-r.js](file:///d:/Trae/temp_20261022_02/assets/js/labs/lab-ohm-r.js#L126-L129) 用 `slider < 0.9` 提示“没移到最大端”，均忽略了下端接的是 A 还是 B。

**结论**：接 A（左）时显示与判定恰好正确；接 B（右）时阻值应随滑片右移**变小**，界面却显示变大，且实验二判定滑片方向相反——这就是“电阻判断逻辑不对”。

### 2.2 现有“自由探究”只是每个实验内的模式，不是独立实验室

- 三个实验都有 `guided / free` 双模式（[app.js](file:///d:/Trae/temp_20261022_02/assets/js/app.js#L178-L181)），但自由模式仍受该实验 `palette` 限制，左侧是实验步骤面板，记录表头也绑定该实验。
- 首页卡片由 [experiments.js](file:///d:/Trae/temp_20261022_02/data/experiments.js) 的三条 lab 元数据渲染，[home.js](file:///d:/Trae/temp_20261022_02/assets/js/ui/home.js#L17-L39) 的卡片假设 `steps.length > 0`（会算出 NaN 进度）。
- 因此需要新增独立 lab 元数据 + 独立 `lab-free.js`，并对首页/实验台做少量分支处理。

## 三、变更方案

### 3.1 `assets/js/core/circuit.js`：新增统一的变阻器信息函数

新增 `rheostatInfo(comp, scene)` 并挂到 `SL.circuit`，返回：

```js
{
  slider, max,
  wiring: 'valid' | 'fixed-max' | 'fixed-zero' | 'incomplete' | 'mixed',
  bottoms, tops,          // 下端/上端已接线柱数量
  lower: 'a' | 'b' | null,// valid 时实际使用的下端柱
  active,                 // 当前接入电阻（Ω，保留 3 位）
  maxAtSlider: 1 | 0 | null, // 阻值最大时滑片位置；null=滑片无效
  atMax                   // 当前是否处于阻值最大端（±5% 容差）
}
```

判定规则（依据教材“一上一下”接法）：

| 接线情况 | wiring | active | maxAtSlider | atMax |
| --- | --- | --- | --- | --- |
| 下端 1 个 + 上端 ≥1（A+C/A+D） | `valid` | `slider·max` | 1（最右） | `slider ≥ 0.95` |
| 下端 1 个 + 上端 ≥1（B+C/B+D） | `valid` | `(1−slider)·max` | 0（最左） | `slider ≤ 0.05` |
| 只接下端 A+B | `fixed-max` | `max` | null | true |
| 只接上端 C/D | `fixed-zero` | 0 | null | false |
| 下端 2 个 + 上端 ≥1（三/四柱混接） | `mixed` | `max` | null | true |
| 接线柱 < 2 | `incomplete` | 0 | null | false |

`active` 下限按求解器的 0.001Ω 处理，展示时四舍五入到 0.1Ω。

改造 `solve()` 末尾原本的接线判定块（L424-439）：改为调用 `rheostatInfo`，把完整对象写入 `result.rheostats[comp.id]`，并按 wiring 生成提示：

- `fixed-max`：“滑动变阻器接成了定值电阻（只接下面两个接线柱），滑片不起作用”
- `fixed-zero`：“滑动变阻器只接了上面接线柱，接入电阻几乎为零”
- `incomplete`：沿用原文案
- `mixed`（新增）：“同时接了下端两个接线柱，变阻器被接成定值电阻，滑片不起作用”

其余求解逻辑、`analyseTopology` 不变。

#### （2）新增 `assets/js/labs/lab-free.js`

- `initial()` 返回空场景 `{ components: [], wires: [] }`（完全空白）。
- `example()` 返回“电池组 + 开关 + 小灯泡 + 电流表 + 电压表（并联灯泡）”的入门电路。
- `measure(ctx)`：取第一个电流表/电压表；两者都没有则 toast 提示并不记录；只有电流表记录 I，只有电压表记录 U，两者都有且 I>0.005 时附带 R=U/I。
- 无 `steps`、无 `conclusions`、无额外 tick 规则（不干预学生）。
- 在 [index.html](file:///d:/Trae/temp_20261022_02/index.html#L25-L27) 的 lab 脚本区追加 `<script src="assets/js/labs/lab-free.js"></script>`。

#### （3）`assets/js/app.js` 分支

- `openLab(labId, mode)`：若 `lab.meta.free`，强制 `app.mode = 'free'`，忽略传入的 guided。

- 属性面板：
  - `meta.free` 且元件为定值电阻时，用 `<input type="number" min="0.1" max="1000" step="0.1">` 替代 5/10/15/20 档位按钮，输入即写回 `props.resistance`；

  - 其余实验保持现有档位不变。
- `addFromPalette()` 对 sandbox 的电阻默认 10Ω、非 unknown（不在 free 实验里隐藏真实阻值）。

## 五、影响面与风险

- `result.rheostats[id]` 结构新增字段，旧调用仅读 `wiring`，兼容。
- `atMax` 容差 5%，与原来 0.95/0.9 的容差接近；实验二判定从“滑块位置”变为“实际电阻最大端”，接 A 时行为不变。
- sandbox 为空场景时，`home.js` 进度计算必须分支，否则 `0/0` 产生 NaN。
- 自定义电阻值需限制在 0.1–1000Ω，避免 0Ω 导致求解矩阵奇异。
